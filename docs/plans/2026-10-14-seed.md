# `/quality-code:seed` Implementation Plan

**Goal:** A data-only command, `/quality-code:seed <KEY> [--path <spec>]`, that writes the test data a
ticket needs (builder calls for Vitest, route stubs for Playwright), generalized from the warehouse
plugins' `/seed` and AGT-16's known dataset. Decided in Jira AGT-87; commits tagged AGT-44.

**Spec:** `docs/specs/2026-10-14-seed-design.md` (read it first).

**Tech Stack:** Node ≥ 18 built-ins only, `node --test`, Claude Code plugin commands.

## Global Constraints

- No npm dependencies: imports are `node:*` or relative only.
- Style: 2-space indent, single quotes, no semicolons.
- No project values under `plugins/quality-code/core/**` (CI greps `FIC|teamsystem\.atlassian|customfield_11707|Giacenza|Magazzino|warehouse`, and `AGT|FIC` under `core/guides`). Examples use `ABC` keys.
- Do not touch `commands/write.md`, `commands/start.md`, `core/pipeline/`, `core/cli.mjs`, `core/setup.mjs` (changed by other work), nor README, CHANGELOG, versions, `.github/`, `examples/`, parity.
- `npm test` passes except the two known container failures ("add on a read-only ticket file", "timeout kills the whole process group, grandchildren included").

## Tasks

### Task 1: the `seed` config block

- [x] Add `seed` to `FIELDS`. Validate: an object; only `builders`, `dataset`, `stubsFrom`.
  `builders`: Vitest only, 1–10 unique relative files (not folders). `dataset`: a relative `.md`.
  `stubsFrom`: Playwright only, a relative folder ending in `/`. Each error names its field.
- [x] `seedOf(config)` → `{ builders: [], dataset: null, stubsFrom: null }` defaults.
- [x] Schema block, `additionalProperties: false`, the vitest path pattern for every path.
- [x] Tests: valid per adapter, defaults, adapter restrictions, each wrong part, the schema.

### Task 2: the guide

- [x] `core/guides/seed-data.md`: what to seed (one row per fact, every named field, exact values,
  seed the cause, unique ids), values as the API stores them, no real data (placeholders, never a
  developer's database), builder calls (only existing, FK order, idempotent, the dataset first),
  route stubs (copied shapes, broad first, shared endpoints not repeated), never.

### Task 3: the command

- [x] `commands/seed.md`, steps: check (with `--path`), ticket (`ticket-eval` steps 1–3, no score,
  and why), dataset, source (builders card / stub search, stop instead of guessing), plan card,
  write, output (print, or `--path` inside `run start` / `run stop`).
- [x] `test/seed-command.test.mjs` pins the key strings, as `write-command.test.mjs` does.

### Task 4: docs

- [x] This plan and the spec.
- [ ] README and CHANGELOG (left to the release: a "Seed test data" row in "What you can do today",
  the `seed` block in "The config file", a CHANGELOG entry).

## Review Focus

1. **A builder name that is not exported** by the configured files. Expected: never used; the
   command lists the exported functions first and calls only those.
2. **A Playwright endpoint with no existing stub.** Expected: the command stops with the "I never
   guess them" line, writes nothing.
3. **`--path` on application code** (`src/orders.ts`). Expected: refused as not a spec; and a spec
   inside a forbidden boundary is denied by the hook, because the write runs inside the run marker.
4. **`builders` in a Playwright config.** Expected: a validation error naming `seed.stubsFrom`.
